# General four-choice questions («پرسش‌های عمومی») — D226 slice 5b

Owner (2026-10-12): beside the price questions, a place to define ordinary four-choice questions that anyone can answer; each must be defined under its own category (topic).

## Content
- Table `trivia_questions` (migration 0083): `topic_id` (required: a question always lives in a topic), `text_fa`, `option_a..d`, `correct_index` 0–3, `explanation_fa`, `age_track`, `status` (draft | approved | retired). No JSON column (D63).
- Topics are the same `puzzle_topics` the themed rounds use; the admin makes them in «ساخت پازل ← موضوع‌ها».
- Admin tab «پرسش‌های عمومی»: list by topic and status, create / edit (topic, question, four choices, which is right, optional explanation, age track), retire / re-activate. Rules (`triviaInputSchema`): topic required and known, 4 different choices, an index 0–3.

## Playing (`/trivia/*`, switch `feature.trivia`, per-game count `trivia.questions` = 8)
- `GET /trivia/topics`: topics with ≥ 1 approved question in the player's track pool, with the counts. `POST /trivia/start {topicId?}`: a game on one topic or a mix; `503 no_questions` when nothing can be asked. `POST /trivia/:id/answer {index, picked}`.
- The choices are shuffled when the game starts (`shuffleTrivia`, seeded); the view never carries the right index. The answer to a question returns `{pickedIndex, correctIndex, correct, explanationFa}`; answering a question twice returns the first answer. One point per right answer; no coins or XP yet (`onFinished` hook exists for later).
- Age tracks: same rule as the price-only mode (`priceOnly`; kids do not get it); the pool is the player's `puzzleTracks`.
- Mobile: a home button «پرسش» (second row), `TriviaScreen`: topic grid + «ترکیبی», then question cards with the verdict (green / red) and the explanation after each tap.

## In a match (duel and private table, 1v1)
- Admin setting `match.trivia_rounds` (0–10, default 0 = off), read when a match starts. After the boards, and after the price round when there is one, both sides answer the same N approved questions, blind and at the same time (`packages/shared/src/trivia/round.ts`, pure state machine; `MatchService` runs it like the price round).
- Questions: the match's own topics first (themed matches), then the whole bank in the players' track pool; choices are shuffled per match (`shuffleTrivia`). Fewer questions than asked is fine; none at all = the match ends as before.
- A question closes when both have answered or `turnSeconds` pass (no answer = wrong). Each right answer is one point, added to the price-round wins before `resolveWinner` / `finalScores`, so the same rules apply (a locked-out side still cannot win off them).
- Wire: `match:state.triviaRound` (never carries the right choice or the rival's pick before the reveal), `trivia:submit {index}`, error `NO_TRIVIA_ROUND`, `match:ended.triviaRound` (everything public). Bots answer right with their level's accuracy.
- Mobile: `duel/DuelTriviaRound.tsx` replaces the board like the price round; the result page shows the right answers of each side.
- Adult look (`duel/DuelTriviaRoundAdult.tsx`, design `docs/design/adult/Dozari Adult - Quiz Duel`; used by both the board duel's question round and the standalone question duel (`trivia/TriviaDuelScreen.tsx`); kid/teen keep `DuelTriviaRound.tsx`): while asking, a header with progress pips, a score strip (you · clock ring · rival, with streak and the rival's «thinking / answered» state) and four 60px answer rows with letter tags; once a question is revealed the rows shrink to 34px (right green ✓, wrong red ✕, «تو»/«حریف» pills) and a «شرح» card shows who got the point, «چرا «…»؟» with the explanation and a «سؤال بعدی» button that fills over 8 s (client-only hold; the server's own timing is unchanged).
- No coin wager on trivia rounds. A table's own choice of the count and 2v2 are not built (the setting applies to every 1v1).

## Question duel («دوئل پرسشی») — D234
Owner (2026-10-14): beside «پرسش» (solo), a live 1v1 that works like the board duel's search: find a rival, start, answer the same questions. The only choice is a topic or random.
- Home: a second button «دوئل پرسشی» next to «پرسش» (`feature.trivia_duel`, same age-track rule as the other question/price modes: kids do not get it). `TriviaDuelScreen`: topic grid + «🎲 تصادفی» → the same diamond search screen as the board duel → versus card (3 s, `TRIVIA_DUEL_INTRO_MS`) → `DuelTriviaRound` → result card with a review of every question.
- Own service, not a board match: `apps/server/src/realtime/trivia-duel.ts` (`TriviaDuelService`, in memory) runs the shared `trivia/round.ts` state machine; the board-duel `MatchService` and its queue are untouched. Lines are per topic: a topic player meets the same topic or a random one (that topic is played); two randoms get a mix; two different topics never meet. Pairing also needs the same question pools (age track). Questions come from the approved bank in the pool, choices shuffled per game (`trivia.duel_questions` = 8, `trivia.duel_seconds` = 15 per question; a question closes when both answered or on the clock).
- Bot fallback like the board duel: a waiting human gets an undisclosed bot after `bots.fallback_seconds` (+ jitter); the bot answers right with its level's accuracy (`BotDriver.planDuelAnswer`). Bots and humans in a question duel are invisible to the board-duel queue and vice versa (`ALREADY_IN_MATCH` / `ALREADY_QUEUED`); a private table starting a match for someone mid question duel is not guarded.
- Wire (`socket/events.ts`): `tduel:join {topicId?}`, `tduel:leave`, `tduel:answer {index}`, `tduel:resume`; server `tduel:found`, `tduel:state` (own `TriviaRoundView`: never the right choice nor the rival's pick before the reveal), `tduel:ended {winner, reason: played|forfeit, scores, round}`; the search clock reuses `queue:status`. Errors: `NO_QUESTIONS` (join on an empty topic), `FEATURE_OFF`, `MAINTENANCE`, `ALREADY_IN_MATCH`, `ALREADY_QUEUED`, `NO_TRIVIA_ROUND`. A socket (re)connect re-sends the running game.
- Winner = more right answers (`triviaWinner`), equal = draw. Leaving a running game (or the screen) forfeits it to the rival; a dropped connection does not stop the clock (unanswered = wrong).
- Reveal: when both have answered a question the app colours it in place for ~3 s with **both picks tagged on the choices** («تو» / «حریف»), a banner (both / only you / only the rival / nobody), a «+۱» pop, the running score and a 🔥 streak from 2 right in a row (`revealKind`, `revealScores`, `yourStreak` in shared). Effects: a draining clock bar with a tick + buzz in the last 5 s, a buzz on tapping and on every reveal (double tap for a point, long for a miss), shake / pop on the choices, confetti for a win, rain for a loss (`DuelTriviaRound`, `TriviaDuelScreen`; buzz honours the vibration preference).
- XP: a finished game pays the board duel's XP to each human (`duel` base + win bonus; a leave counts as a loss). Not in the question duel: daily cap, level gate.

## Coins («سکه») — D235
Owner (2026-10-14): starting a solo question game or a question duel costs coins — solo less, duel more — XP stays, and the numbers must be worth it for the player and a small sink for the house.
- Settings (defaults in `config/topics.ts`, admin group «اقتصاد»): `trivia.solo_fee` = 3, `trivia.solo_refund_percent` = 75, `trivia.duel_fee` = 12 (below the board duel's 20: quicker, less skill). 0 = free. The house cut is the board duel's `duel.house_cut_percent` (10 %).
- **Solo («پرسش»)**: the fee is taken when the game starts (`POST /trivia/start` → 402 `insufficient_coins` when the player cannot pay; an anonymous game is free). If at least 75 % of the answers are right the fee comes back at the last answer and the game counts as a win for XP, else as a loss; so a good player plays for free and a poor one pays ~3 coins. Reasons `trivia_entry`, `trivia_refund`; idempotent per game.
- **Question duel**: the fee is checked at `tduel:join` (`INSUFFICIENT_COINS`) and taken from each human when the pair is made (a bot's is covered by the house). Winner: pot minus the cut (12×2 → 21, net +9); draw: fee minus the cut back (10, net −2); a bot rival: the human wins the full pot and only ever risks their own fee. If someone can no longer pay at that moment the pairing fails for them only (`tduel:refused`) and the other keeps waiting. Reasons `trivia_entry`, `trivia_payout`, `trivia_refund`; pure math `triviaDuelAwards` / `triviaDuelNet` in shared. `tduel:found.fee` and `tduel:ended.coins` (net) feed the UI.
- **Leaving** a running question duel (✕, the phone's back, leaving the screen, or the search's cancel after the rival was found) asks first, then forfeits like a board duel: the fee goes to the rival, XP counts a loss, and the leave is logged for the leave penalty (`leave.*`, day ban `LEAVE_BANNED`, badge) — `TriviaDuelDeps.onLeave` → `LeaveService.record`. A bot never gets a leave logged. A dropped connection is not a leave (the clock runs on).
- Sim note: both are small sinks. Solo ≈ 0–3 coins per game; duel ≈ 2.4 coins per game on average (the cut of the pot) for equal players. They are not faucets: no consolation, no free matches, no rescue top-up.

## Rematch — D235
- After a **played** game (not a forfeit) either side has `TRIVIA_DUEL_REMATCH_SECONDS` = 30 s to ask for another game with the same rival and topic: `tduel:rematch`. A bot rival, or a rival who already asked, starts it at once (fees taken again); otherwise the rival gets `tduel:offer {asked}` («حریف بازی مجدد می‌خواهد!»). When the window ends, or either side starts something else, both get `tduel:offer {expired}`. A side that cannot pay gets `INSUFFICIENT_COINS`. The result card shows the button, its waiting / accept states, and the reason when it is gone (forfeit / expired).

## No repeats («سؤال تکراری») — D236
Without memory every game is an independent random draw of 8 from the topic, so with N questions the chance of at least one repeat versus the previous game is ~99 % at N=20, 78 % at 50, 50 % at 100, 28 % at 200, 12 % at 500. Now each player has a memory:
- Table `trivia_seen(user_id, question_id, seen_at)` (migration 0093), the newest `TRIVIA_SEEN_KEEP` = 500 rows per player (older ones are dropped on every write). Only humans; guests and bots keep none.
- A question counts as seen when it is **revealed** (solo: when answered; question duel: when both answered or the clock ended it), so an abandoned game does not burn the rest. The board duel's question round marks its questions when it opens.
- Drawing (`pickFreshTrivia`, shared, pure; `drawTrivia`, server): from up to `TRIVIA_POOL_FETCH` = 400 random approved questions of the topic (a chosen topic is never padded from others; a themed board duel pads from the bank), rank by *how many of the players saw it* (0 first), then *longest ago*, ties random. So a bank bigger than the history never repeats, and a small one cycles through its oldest questions instead of resetting. In a duel both humans' memories count (what neither saw first, then what only one saw); a bot has none.
- Rematch needs nothing extra: the game just played was marked seen for both, so the next draw avoids it while the topic has enough other questions.
- Rule of thumb for content: no repeats for the next G games while the topic has at least (G+1)×8 approved questions (100 → about 12 games). Near-duplicate wording of one fact is not detected here.


## Difficulty («سختی سؤال») and level matching — D238
Owner (2026-10-14): record each question's difficulty now; later, when the bank is big, serve questions by the player's level, switchable from the panel.
- **Recorded**: `trivia_questions.difficulty` 1 easy · 2 medium · 3 hard (default 2; the admin form has a «سختی» field, a workshop author suggests one and the admin can change it when approving). **Measured** from play: `plays` (answers by humans, bots excluded) and `right_count` are bumped when a question is revealed in solo, the question duel and the board duel's question round. `measuredDifficulty` (shared) turns them into 1/2/3 once a question has `TRIVIA_MEASURE_MIN_PLAYS` = 30 answers (≥ 75 % right = easy, < 45 % = hard).
- **Admin «پرسش‌های عمومی»**: a difficulty badge per question, a filter, the counts per level, and — next to the set value — «۴۰ بار جواب داده شد، ۹۰٪ درست ← اندازه‌گیری: آسان» with a one-click «قبول آسان» (`PATCH /admin/trivia/:id {difficulty}`). The list reports `measured` per question.
- **Level matching** — admin setting `trivia.level_matching` (default **off**: draws stay random). When on, a draw's *target* = the player's level → easy below `trivia.level_medium_from` (6), medium below `trivia.level_hard_from` (15), hard from there; a duel uses the two players' average level, bots count for nothing. Ranking in `pickFreshTrivia`: **unseen first (D236), then closest to the target, then oldest seen** — so level matching never brings repeats back and a thin level is simply filled from the nearest one. Turn it on once each level has a few dozen questions per topic (the panel shows the counts).
